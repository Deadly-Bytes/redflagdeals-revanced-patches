# Topic-list unread-cache investigation — 2026-10-04

## Scope

This used an Android 14 / API 34 emulator. Manual diagnostic APKs established the cause, followed by a full ReVanced bundle build and application to the unmodified stock 1.11.7 APK. The resulting APK was installed and tested; physical-device testing remains pending.

## Confirmed cause and result

- The original topic-list response from the shared `/api/topics` cache reported `Age: 75` and `has_new_post=false` for all 15 returned topics. Its `can_reply` count was also zero.
- Fetching the exact topic for the first listed item returned `has_new_post=true`, proving the list response was stale relative to the topic response.
- Adding a unique `rfd_unread_nonce` query parameter to the exact forum topic-list GET returned a fresh list with `has_new_post=true` for 14 of 15 topics and `can_reply=true` for 9 topics. Screenshots from that run showed the corresponding blue dots.
- After reading two threads, returning with Back, and refreshing the list, the fresh response reported 13 of 15 topics with `has_new_post=true`. This matches the server flag changing as the threads were read.
- The production-helper test APK retained these visible read/unread differences after an update installation using the same signing certificate. Signature and alignment checks passed; app data was retained.
- A three-page thread retained its blue dot after returning from page 1. With the production helper installed, navigating to page 3/3 and returning with Back cleared that thread's dot while nearby unread threads retained theirs.
- Refreshing the list again kept that three-page thread read (35 replies) while neighboring unread rows still showed dots. No crash-buffer entries were present.

The 31 isolated helper contract checks, 24 existing reply-control checks, and eight release-safeguard tests passed. Independent source and release reviews found no blocker.

## Implementation boundary

The production helper is limited to GET requests for exact HTTPS `forums.redflagdeals.com/api/topics`. It preserves the existing request's cookies, headers, body, and authentication state, and appends only a nonce query parameter. The app continues to use the server's `has_new_post` flag; the existing last-page/Back model-return behavior remains in place so a cleared server flag is reflected in the list.
